About

My foundation is audit and PM. I've led full audit lifecycles — planning through issue validation — under SOX, GLBA, and Government Auditing Standards, and maintained continuous audit‑readiness for NERC CIP (CIP‑002–013), including evidence management and direct auditor coordination. As a PMP, I bring real project structure to compliance work: scoped risk registers, remediation roadmaps with clear ownership, and cross‑functional stakeholder management.

Beyond policies, I'm now building the automation that proves it holds, some of which include:

  • Terraform‑managed GCP Org Policy guardrails, enforcement validated by deliberately trying to break them.
  • Keyless CI/CD auth (OIDC/Workload Identity Federation) for GitHub Actions across AWS and GCP.
  • A policy‑as‑code compliance gate (OPA/Conftest, tfsec) that caught and blocked a real high‑severity misconfiguration.
  • Machine‑readable OSCAL control documentation so assessors can verify claims via evidence links directly.

Alongside my practitioner work, I teach computer programming (Python, C++), operating systems, computer networks, distributed systems, cloud computing, system administration, and information security at Liberty University — the exact stack that underpins the infrastructure I secure. Teaching operating systems and networks at a fundamentals level keeps me sharp on how systems actually fail, not just how compliance frameworks say they should be controlled; teaching cloud computing and distributed systems keeps me current on the architectures I'm building guardrails for in AWS and GCP. I'm also a PhD candidate researching AI governance, AI model supply chain integrity, and adversarial risk, which keeps me close to where GRC is headed next, not just where it's been.

I love owning compliance programs end‑to‑end — audits, questionnaires, risk registers, vendor assessments — while building the automation that lets those programs scale instead of drowning in spreadsheets.

Outside of work, I'm a dedicated wife and mom, passionate about helping marriages thrive according to God's original design.

PROJ‑01Lab 2.3

Compliant Cloud Storage Baseline

Stack: Terraform, AWS S3, AWS IAM
Controls: NIST SP 800‑53 — SC‑28, AC‑3, AU‑3, AU‑6, CM‑6

Built a hardened S3 bucket in Terraform satisfying five NIST 800‑53 controls end‑to‑end: encryption at rest, blocked public access, dedicated access logging, and enforced tagging/versioning. Captured pre‑ and post‑deploy compliance state as machine‑readable JSON evidence rather than console screenshots — the evidence‑as‑code pattern used throughout.

PROJ‑02Lab 2.4

Compliance‑as‑Code Terraform Modules

Stack: Terraform, GCP Cloud KMS, GCP Storage, GCP IAM
Controls: NIST SP 800‑53 — SC‑28, AC‑2, CM‑6

Designed a reusable Terraform module bundling a KMS keyring, a customer‑managed rotating key, IAM bindings, and a hardened bucket into one deployable unit — with the security baseline locked inside so consuming teams can't opt out. Validated that dev and prod inherited an identical, non‑negotiable posture.

PROJ‑03Lab 2.5

IaC as Tamper‑Evident Compliance Evidence

Stack: Terraform, AWS S3 Object Lock, Bash, SHA‑256, Cosign
Controls: Evidence integrity, attribution, reproducibility

Built a write‑once evidence vault using S3 Object Lock and a capture script that hashes and archives Terraform state so it can't be altered or quietly deleted. Established the three properties auditors actually care about — integrity, attribution, reproducibility — replacing "trust me" screenshots with cryptographically verifiable proof.

PROJ‑04Lab 3.3

Policy‑as‑Code: Rego Compliance Policies

Stack: Open Policy Agent (OPA), Rego, GCP fixtures
Controls: Custom deny‑rules mapped to NIST control IDs

Authored and unit‑tested OPA policies in Rego that inspect a Terraform plan and automatically reject it on a control violation — before anything deploys. Wrote deliberate policy‑violation test cases to prove each rule catches what it claims to.

PROJ‑05Lab 3.4

Cross‑Cloud Policy Gate with Conftest

Stack: Conftest, OPA/Rego, AWS, Bash
Controls: Same control IDs (e.g. SC‑28) enforced across AWS and GCP

Ported the Rego policy library written for GCP to run against AWS Terraform plans, proving a control ID travels across cloud providers even when its implementation doesn't. Delivered policy-gate.sh — one portable script a CI pipeline can call to fail‑closed regardless of cloud.

PROJ‑06Lab 4.3

GRC Evidence Pipeline

Stack: GitHub Actions, OIDC, Conftest, tfsec, AWS
Controls: Continuous monitoring, automated audit trail generation

Built a GitHub Actions workflow that runs on every pull request: authenticates to AWS via OIDC (no long‑lived credentials), plans the Terraform, runs the Conftest policy gate, scans with tfsec, and uploads a named evidence artifact. Enforces compliance and documents it automatically.

PROJ‑07Lab 4.4

Evidence Chain of Custody with Keyless Signing

Stack: Sigstore, Cosign, Fulcio, Rekor, GitHub OIDC
Controls: Authenticity, integrity, timeliness, preservation

Wired Sigstore's keyless signing into the CI pipeline so every piece of evidence is cryptographically signed and timestamped using the workflow's own OIDC identity — no private keys to manage or leak. Signatures are publicly verifiable in Rekor's transparency log.

PROJ‑08Lab 5.2

AWS Security Services Baseline

Stack: Terraform, AWS CloudTrail, AWS Config, AWS Security Hub
Controls: NIST 800‑53 — AU‑2, AU‑12, AU‑10, CM‑2, CM‑6, CM‑8, RA‑5, SI‑4

Stood up the always‑on, account‑level AWS backbone under the CI evidence pipeline: multi‑region CloudTrail, AWS Config resource history, and Security Hub findings mapped to NIST 800‑53. Moved "continuous monitoring" from a compliance‑document phrase to a live, queryable JSON feed.

PROJ‑09Lab 5.4

GCP Security Services Baseline

Stack: Terraform, GCP Org Policy, Workload Identity Federation, Cloud Audit Logs
Controls: NIST 800‑53 — CM‑6, AC‑2, AC‑3

Deployed GCP's identity‑first, preventive model: Org Policy constraints that reject non‑compliant resources at the API call itself, Workload Identity Federation to eliminate downloadable service‑account keys, and Data Access logging across storage, KMS, and IAM. Demonstrated the detective‑vs‑preventive distinction in practice.

PROJ‑10Lab 6.1

OSCAL Compliance Mapping

Stack: NIST OSCAL, compliance‑trestle, Python
Controls: NIST SP 800‑53 Rev 5 (machine‑readable catalog/profile/component mapping)

Authored NIST OSCAL component definitions mapping Terraform‑enforced AWS S3 controls to NIST SP 800‑53 Rev 5 — validated against the official schema. Found and remediated a missing audit‑logging control during authoring, then verified the evidence chain with SHA‑256 checks and Cosign signatures.

PROJ‑11

Custom Compliance Checks for Off‑the‑Shelf GRC Gaps

Stack: Python, boto3, moto, Faker, PyYAML, pytest
Controls: SOC 2 / ISO 27001 — MFA enforcement, public storage exposure, access‑revocation timing, periodic access review

Built a proof‑of‑concept demonstrating exactly where off‑the‑shelf GRC platforms (e.g. Vanta, Drata) stop covering an organization and where custom code becomes necessary: checks a vendor connector already handles (MFA enforcement, public storage exposure) alongside checks only custom code can perform against a company's own internal systems (timely access revocation after termination, periodic access reviews). Simulated AWS with moto and generated realistic fake HR/access data with Faker to test entirely offline — no real cloud account or company data required. Found and fixed a logic bug where the termination‑access check only tested presence/absence rather than actual revocation timing.

PROJ‑12

Automated Compliance Evidence Pipeline & Slack Alerting

Stack: Python, YAML control catalog, pytest, Slack SDK (Block Kit), GitHub Actions
Controls: SOC 2 & ISO 27001 control catalog, continuous monitoring

Extended the compliance checks into a full evidence pipeline: results are written as timestamped JSON evidence, then compiled into a human‑readable Markdown audit report. Built a Slack bot that reads a single YAML control catalog mapping each check to SOC 2/ISO 27001 requirements, evaluates results against defined thresholds, and posts formatted Block Kit alerts to a dedicated channel for any failing control — authenticated with a bot token scoped to chat:write only. Scheduled the full pipeline via GitHub Actions so alerts fire daily with no manual step.

PROJ‑13 · CAPSTONE

Automated Audit‑Defensible Evidence Pipeline

Stack: Terraform, GitHub Actions, OPA/Conftest, tfsec, Cosign/Sigstore, OSCAL, AWS
Controls: Primary framework selected and defended (HIPAA Security Rule / SOC 2 Type II / CMMC Level 2), mapped to NIST 800‑53/800‑171

Governed a pre‑existing, non‑compliant Patient Intake API for a simulated 50‑person telehealth company, closing eight intentional compliance gaps within a 30‑day scenario constraint — without slowing engineering down. Integrated every layer built across the portfolio into one repository: policy‑as‑code gates, signed evidence pipeline, native cloud monitoring baselines, and an OSCAL component definition — then structured the full technical implementation and audit narrative around the chosen framework.
